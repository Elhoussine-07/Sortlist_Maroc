# Double validation du JWT (Gateway + Frappe)

Le workflow du JWT repose sur un **secret partagé** identique entre Frappe et l'API Gateway. Lors de la connexion, Frappe génère un JWT en signant le contenu (email et rôle de l'utilisateur) avec ce secret, puis le retourne au frontend. Le frontend stocke ce JWT et l'envoie dans l'en-tête `Authorization` de chaque requête protégée. L'API Gateway reçoit la requête et effectue une **première validation** : il recalcule la signature du JWT à l'aide de son propre secret et la compare avec celle du token. Si elle correspond, cela prouve que le JWT a bien été généré par Frappe et qu'il n'a pas été altéré. L'API Gateway extrait alors l'identité de l'utilisateur et l'injecte dans les en-têtes HTTP avant de transmettre la requête à Frappe. Frappe, de son côté, effectue une **seconde validation** : il re-vérifie la signature du JWT avec son propre secret, pour s'assurer que le token est authentique, même si l'API Gateway venait à être compromis. Cette double validation garantit que seules les requêtes authentifiées et autorisées atteignent les données sensibles, tout en déchargeant les microservices de la gestion de la sécurité.
